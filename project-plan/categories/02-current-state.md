## Проверка свежести и retrieval источников RAG / RAG source freshness and retrieval check — 2026-10-22

**RU:** В текущем backend официальные страницы загружаются только по точному allowlist; текст в RAG-кэш допускается только для URL с зафиксированной лицензией. Автоматический монитор запускается вместе с backend, проверяет новые/просроченные URL примерно раз в 24 часа и повторяет `network_error`/`unavailable` через 6 часов. Web-фрагмент доступен retrieval только после успешной проверки не старше 48 часов; метадата издателя и время проверки не объявляются доказательством точности урока. Смена страницы создаёт сигнал для редакторской проверки и не переписывает утверждённый урок автоматически. Целевые тесты `test_source_scheduler.py` и `test_trusted_sources.py` прошли: 83 passed; полный backend-набор в Windows-сессии на commit `f784c51` тоже прошёл: 608 passed за 157 секунд. Это тесты backend с контролируемыми ответами, а не live-проверка внешних сайтов, фактов уроков или приёмка macOS-приложения.

**EN:** The current backend fetches official pages only from an exact allowlist; text enters the RAG cache only for URLs with a recorded reuse license. The automatic monitor starts with the backend, checks new or due URLs about every 24 hours, and retries `network_error`/`unavailable` after 6 hours. Web excerpts enter retrieval only after a successful check no older than 48 hours; publisher metadata and check time are not presented as proof that a lesson is accurate. Page changes create an editorial-review signal and do not automatically rewrite approved lessons. Focused `test_source_scheduler.py` and `test_trusted_sources.py` passed: 83 passed; the full backend suite also passed in the Windows session at commit `f784c51`: 608 passed in 157 seconds. These are backend tests with controlled responses, not live checks of external websites, lesson facts, or macOS app acceptance.

### Официальные первоисточники в RAG-карточках

Учебный индекс сохраняет рядом с каждым Markdown-уроком список canonical title/URL только для четырёх утверждённых HTTPS-доменов. Данные мигрируют в уже существующей SQLite базе с пустым списком по умолчанию; обновляются вместе с файлом при индексировании. `/chat/stream` передаёт их вместе с `[K#]`-ссылкой модели и в SSE-метаданных, а SwiftUI показывает проверяемые внешние ссылки с повторной проверкой схемы и точного host. Чужие URL не передаются модели как первоисточники и не становятся ссылками в UI. Это provenance для локального урока, не загрузка страницы, не независимый фактчекинг и не полноценный web-RAG. macOS-сборка SwiftUI-части этого изменения всё ещё требует Xcode CI.

Для commit `fbf18e5` локально пройдены 295 backend-тестов и Ruff/compileall. GitHub Actions run [37311093375](https://github.com/invinby/coli-dev/actions/runs/37311093375) завершил все три jobs без единого шага и без доступных логов; этот запуск не подтвердил backend CI или Xcode-сборку. Причина отказа в данных run не раскрыта. Текущий код требует успешной CI-сборки и запуска SwiftUI на Mac перед заявлением о готовности.

В текущем срезе проверки источников есть обратно-совместимая миграция SQLite: для каждой разрешённой страницы сохраняются только заголовок, краткое описание, SHA-256 нормализованного текста и дата проверки. До 512 KiB HTML читается только в памяти, редиректы запрещены; полный текст не хранится и не индексируется. Панель Sources показывает эти метаданные отдельно от редакторской даты урока и HTTP Last-Modified, ищет по названию источника, URL, предмету и пути урока, фильтрует очередь проверки. Контентные/HTTP изменения, первая baseline-проверка старой записи и непригодные ответы требуют внимания редактора; сама проверка не переписывает урок и не подтверждает факты. Это изменение ещё требует backend CI, SwiftUI-сборки и запуска на Mac; локальные тесты в этой итерации не запускались.
