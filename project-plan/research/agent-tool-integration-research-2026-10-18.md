# Агентные инструменты и границы интеграции / Agent tools and integration boundaries

**Дата проверки / Checked:** 2026-10-18
**Объём / Scope:** первичные источники проектов и текущая локальная копия ColiDev; код не менялся. Оценка относится к Cause & Course как обучающей платформе и к ColiDev как текущему прототипу.

## Короткий вывод / Short answer

**RU:** Не встраивать все четыре продукта в учебный рантайм. ColiDev уже имеет собственную оркестрацию ролей, выбор моделей, OpenRouter, локальную Ollama, RAG и правила блокировки платных маршрутов. OpenRouter — провайдер/маршрутизатор моделей; остальные — инструменты/среды агентов, и само добавление ещё одной оболочки не даёт новых знаний или гарантии качества. Для разработки команды разумно отдельно оценить **OpenCode** в изолированной ветке; **Freebuff** — только как добровольный внешний coding-agent после проверки приватности; **Hermes** — позже для ограниченных исследовательских/автоматизационных задач; **OpenClaw** — только если появится конкретный сценарий Discord/мессенджера. Не запускать Hermes и OpenClaw одновременно как второй «консилиум».

**EN:** Do not embed all four products into the learning runtime. ColiDev already has role orchestration, model selection, OpenRouter, local Ollama, RAG, and paid-route blocking. OpenRouter routes model inference; the others are agent tools/runtimes, and another harness does not itself add knowledge or guarantee quality. For team development, evaluate **OpenCode** separately in an isolated branch; treat **Freebuff** as an optional external coding agent only after a privacy review; consider **Hermes** later for constrained research/automation; consider **OpenClaw** only for a concrete Discord/messaging use case. Do not run Hermes and OpenClaw together as a second “council.”

## Что обнаружено в ColiDev / What the repository shows

- `README.md` describes a native macOS learning app with a local Python service; its current tutor has parallel drafts, a critic, a verifier, and final synthesis. Existing runtime provider options include Ollama, Gemini, Kimi, OpenRouter, and a custom OpenAI-compatible route. `.env.example` already has `OPENROUTER_API_KEY`; the app has per-role routing and a free-only cost gate. Relevant implementation: `01_Projects/orchestrator.py`, `project-plan/categories/04-ai.md`, `.env.example`.
- `03_Resources/freebuff_system_prompt.md` is a historical prompt describing “Freebuff” as MiMo 2.5 through OpenRouter and a coding mentor. It is not an integration manifest or proof that the Freebuff service/model is installed.
- In the current Python orchestrator, `freebuff` is a **legacy debate-log label** for the critic; `_agent_label()` renders it as `Ollama (критический разбор)`, and the critic calls `_ask_auto_agent_role("critic", ...)`. That is local Ollama or the configured role route, not a Freebuff API call. The prompt’s provider/model description and today’s Freebuff product should not be conflated.
- The official Freebuff project now describes a suite of coding products and a hosted model service. Its published privacy policy is dated 2026-10-13 but says it becomes effective 2026-11-12 (future as of this audit); it says Desktop/CLI agents run with the device account's permissions, may access files/environment variables outside the project, and content they read becomes service Prompt/Project Data. The policy also describes advertising-related analysis and AI-provider processing. So “runs as a local CLI” does **not** mean inference/context stays local. Recheck effective terms before use; no Freebuff dependency or runtime provider is present in this checkout.

## Роли инструментов / Tool roles and fit

| Инструмент | Что это по первичным источникам | Возможное место рядом с Cause & Course | Решение и границы |
|---|---|---|---|
| **OpenCode** | Открытый coding-agent для работы с репозиторием; поддерживает провайдеры, в том числе OpenRouter, MCP и ACP. Его разрешения могут требовать подтверждение, запрещать или разрешать инструменты; по умолчанию разрешения довольно открытые. | Разработка самой платформы: отдельный кодовый агент для задачи в выделенной feature-ветке, ревью человеком и CI. | **Лучший кандидат только как внешний dev-tool**, не как педагогический агент. Настроить edit/bash как ask или deny до явного разрешения, ограничить проектный каталог, не выдавать `.env`, Keychain, GitHub write token и доступ к Mac-профилю. OpenRouter уже подключать как provider в OpenCode, если нужно; не создавать второй ключ/маршрутизатор в ColiDev. |
| **Hermes Agent** | Общий автономный агент с CLI, памятью/skills, несколькими моделями и провайдерами, делегированием, MCP и messaging gateway; имеет локальный или sandbox/remote terminal. | Позже — отдельный вспомогательный исполнитель для исследовательского прототипа: собирать предложения по источникам или формировать черновик редакторской задачи, которую человек проверит. | **Не включать в основной runtime сейчас.** Он дублировал бы роли/память/инструментальную оркестрацию и добавил ещё один контур доступа. Если пилотировать, то в sandbox, без shell на пользовательском Mac, с read-only доступом только к тестовым материалам, сетевым правилам и approvals в fail-closed режиме. Hermes сам поддерживает OpenRouter как провайдера — отдельная маршрутизация не нужна. |
| **OpenClaw** | Self-hosted Gateway для соединения чатов (включая Discord) с агентами, с каналами, tools, plugins, sessions и routing. В документации sandbox **выключен по умолчанию**; плагины выполняются в процессе Gateway и считаются доверенным кодом. | Возможный будущий командный Discord-бот: например, добровольная команда просит ссылку на урок или сообщает о проблеме; не источник истины для курсов и не часть образовательного ядра. | **Отложить до явного сценария.** Он заметно пересекается с Hermes по gateway, каналам, tool access и агентам. Если нужен Discord, выбрать один gateway; включить sandbox, отдельного бота/workspace, allowlist участников и каналов, минимальные tools, без `exec`/browser/файлов по умолчанию. Не давать общему чату доступ к домашней папке, токенам, Obsidian или админ-функциям. |
| **Freebuff** | Сейчас это отдельный coding-agent продукт/CLI/desktop/cloud, который обещает доступ к облачным моделям без собственного API key; это не OpenRouter и не универсальный model gateway. Официальный README раскрывает обработку prompts, traces и файлов для сервиса и возможный анализ для ads/model training. | Необязательное внешнее средство, которым разработчик сам просит разобрать учебный код или сделать независимое ревью. | **Не подключать в приложение.** API/SDK-контракт для встраивания учебного тьютора не подтверждён в просмотренных первичных материалах. Не отправлять ему частные уроки, ученические данные, `.env`, секреты и непубликованные материалы без отдельной проверки политики и согласия команды. Учитывать дневные/региональные ограничения, даже если базовый доступ заявлен бесплатным. |

## Как не дублировать OpenRouter / Avoiding OpenRouter duplication

**RU:** Сохранить одну цепочку внутри продукта: Cause & Course решает учебную задачу, собирает одобренный RAG-контекст, показывает источники и выбирает роль; текущий backend маршрутизирует конкретный inference в Ollama или существующий облачный provider/OpenRouter с теми же privacy/cost gates. Не помещать OpenRouter за Hermes, затем ещё за OpenClaw, и не вызывать ещё один консилиум после ответа ColiDev. Каждая дополнительная оболочка может добавить запросы, задержку, передачу того же контекста новому оператору и неочевидные расходы. Агентные coding tools оставить на стороне разработки, вне ответа ученику.

**EN:** Keep one product path: Cause & Course owns the learning task, approved RAG context, citations, and role selection; the existing backend routes each inference to Ollama or the already configured cloud provider/OpenRouter under the same privacy and cost gates. Do not nest OpenRouter behind Hermes and OpenClaw, then launch another council after ColiDev has answered. Each extra harness can add calls, latency, another party receiving the same context, and opaque cost. Keep coding agents on the development side, outside the learner’s answer path.

## Последовательность внедрения / Safe sequence

1. Complete the current physical-Mac beta acceptance and record failures before expanding integrations. CI is not proof of a user-Mac run.
2. If the team wants an extra coding workflow, try one OpenCode session in a disposable feature worktree with read-only analysis first; then allow specific file edits behind approval. Review diff and test results before merging. Freebuff may be compared only with sanitized/public code and after the team accepts its cloud data terms.
3. Build the learning-source workflow inside ColiDev first: approved first-party/academic sources → cached excerpt with provenance/license/date → RAG citation → editorial review queue when the source changes. Do not let any general-purpose agent silently publish or rewrite lessons.
4. Only if research coordination becomes an actual bottleneck, run a small Hermes pilot against a read-only copy and fixed source allowlist. Measure citations, factual corrections, latency and cost; keep the human editor as release gate.
5. Add OpenClaw only after naming the exact Discord flow and members/permissions. Use either OpenClaw **or** Hermes gateway for the pilot, not both.
